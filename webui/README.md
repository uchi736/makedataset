# rageval Web UI (React 版) — 起動・操作マニュアル

Streamlit 版 (`rageval review` / `rageval stats`) と同じデータ・同じ保存先を扱う、
React 製のレビュー + 分析画面。Streamlit 版はそのまま残っており、併用できる。

- バックエンド: FastAPI ([src/rageval/webapi/](../src/rageval/webapi/))
- フロントエンド: Vite + React + TypeScript (このディレクトリ)
- レビューの書き込み先: **`data/reviewed/<元ファイル名>`** (Streamlit 版と完全に同じ規約)

---

## 1. 必要なもの

| もの | バージョン | 用途 |
|---|---|---|
| Python + uv | 3.12+ / uv 0.8+ | サーバ実行 (`uv sync` 済みであること) |
| Node.js + npm | Node 18+ (動作確認は v20) | フロントエンドのビルド (初回と UI 変更時だけ) |

## 2. 初回セットアップ (1回だけ)

```bash
# リポジトリ直下で
uv sync --extra dev          # fastapi / uvicorn が入る

cd webui
npm install                  # フロントエンドの依存を取得
npm run build                # webui/dist を生成 (型検査込み)
cd ..
```

`webui/dist` は git 管理外なので、クローン直後や UI のソースを変えたときは
`npm run build` を実行し直す。**UI を変えないかぎり2回目以降は不要。**

## 3. 起動

```bash
# リポジトリ直下で
uv run rageval web
```

- 既定で `http://127.0.0.1:8765/` が自動でブラウザに開く
- 終了は Ctrl+C
- 初回アクセス時は「使い方 — 3ステップ」の案内が表示される (右上の「？ 使い方」でいつでも再表示)

### オプション

| オプション | 既定値 | 意味 |
|---|---|---|
| `--port` | `8765` | 待ち受けポート (8000/8003 は vLLM が使用中のため避けてある) |
| `--host` | `127.0.0.1` | 待ち受けホスト。他PCから見せる場合は `0.0.0.0` |
| `--data-root` | `data` | データ置き場。この下の JSONL ディレクトリを画面から選ぶ |
| `--reviewer` | `unknown` | reviewed_by の既定値 (画面のサイドバーからも変更可) |
| `--open/--no-open` | `--open` | 起動時にブラウザを開くか |

例:

```bash
uv run rageval web --port 9000 --reviewer uchi --no-open
```

## 4. 使い方 — 3ステップ

1. **データセットを選ぶ** (サイドバー上段)。
   `raw` = 生成直後 / `filtered` = 判定LLM通過 / `reviewed` = レビュー済み。
   ふだんは `filtered` を開いてレビューする。すでに `data/reviewed/` に同名ファイルが
   あれば自動でその続きが表示される。
2. **「分析」タブで現在地を確かめる**。件数・難易度の配分・品質ゲート通過率が
   目標に届いているかが、目標値つきで見える。
3. **「レビュー」タブで1問ずつ判定する** (既定タブ)。
   ①質問と回答を読む → ②根拠 (黄色の箇所) を確かめる → ③採用/修正/却下。
   判定は即座に `data/reviewed/<元ファイル名>` に保存され、そのファイルが納品物になる。

### タブは3枚

| タブ | 役割 |
|---|---|
| **レビュー** (既定) | 主作業。上部に進捗と「次の未判定へ」ボタン、「未判定のみ表示」の切替。左のリストで任意の問いへ移動 |
| **一覧** | 検索・ソート・状態絞り込みで個別の問いを探す。行クリックで詳細 (生JSON・RAG検証結果まで)、そこから「この問いをレビュー」でジャンプ |
| **分析** | 件数・配分・健全性チェックが上段に常時表示。カバレッジ (25観点) / 品質スコア / RAG検証 / KG-PoC は折りたたみ節で、**該当データが無い節は表示されない** |

### レビュー画面の見かた

- **② 根拠を確かめる**: 引用が原文チャンクと逐語一致するかを機械チェックし、
  一致箇所を黄色でハイライト。✗ が付いた引用だけ目視で突き合わせればよい。
  **照合先チャンクは自動判定** (引用が最も一致する `data/chunks*` を選ぶ。
  どれを使ったかはバナーに表示。固定したいときはサイドバー詳細設定から)
- **③ 判定 (減点式)**: 問題があるときだけチェックを入れる。指摘ゼロならそのまま「採用」
- 「修正」は質問・回答を書き直してから保存 (status = edited)

**キーボードショートカット** (文字入力中は無効):

| キー | 動作 |
|---|---|
| `A` | 採用 |
| `E` | 修正モードに入る |
| `R` | 却下 |
| `N` | 次の未判定へ |
| `←` / `→` | 前の問い / 次の問い |
| `Ctrl+Enter` | (修正モード中) 保存 |
| `Esc` | (修正モード中) キャンセル |

### サイドバー

上から ①データセット ②レビュー者。トラックの表示切替・照合先チャンクの固定・
カテゴリ/ファイル絞り込みは「詳細設定」に畳んである (ふだんは触らなくてよい)。
**左上の ◀ / ☰ ボタンでサイドバーごと隠せる** (レビューに集中して画面を広く使う。
状態はブラウザに記憶され、隠している間も読み込み中のデータ名は上部に出続ける)。

## 5. 開発モード (UI を改造するとき)

ソース変更を即時反映 (HMR) したい場合は、API サーバと Vite dev server を並走させる:

```bash
# ターミナル1: API サーバ
uv run rageval web --no-open

# ターミナル2: dev server (http://localhost:5173 が開く。/api は :8765 へプロキシ)
cd webui
npm run dev
```

改造が終わったら `npm run build` して、以後は `uv run rageval web` だけで動く。

## 6. トラブルシュート

| 症状 | 対処 |
|---|---|
| `webui/dist がありません` (503) | `cd webui && npm install && npm run build` |
| ポートが使用中 | `uv run rageval web --port 9000` など空きポートを指定 |
| 「原文チャンクが見つかりません」 | 全チャンクディレクトリを探しても引用に合う原文が無い状態。`rageval chunk` でチャンクを作り直したか、QA と別コーパスの可能性 |
| バックエンドに接続できません | サーバが起動しているか確認。dev モード時は :8765 の API サーバも必要 |
| 旧スキーマ n 件をスキップ | 古い形式の JSONL 行は表示対象外 (Streamlit 版と同じ挙動)。件数はサイドバーに表示される |

## 7. Streamlit 版との関係

| | React 版 (`rageval web`) | Streamlit 版 (`review` / `stats`) |
|---|---|---|
| 起動 | `uv run rageval web` | `uv run rageval review --in …` など |
| データ切替 | 画面上で切替 (再起動不要) | CLI 引数で指定 |
| 根拠の照合先 | 自動判定 (固定も可) | `--chunks` で指定 |
| レビュー保存先 | `data/reviewed/<元ファイル名>` | 同じ |
| 併用 | ○ (同じファイルを同時に書かないこと) | ○ |

保存形式が同一なので、Streamlit 版でレビューした続きを React 版で開ける (逆も可)。
