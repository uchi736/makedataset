# 問いの作り方 — なぜ「検索で解けない問い」になるのか

この評価が測りたいのは、**答えの原文に質問の言葉が出てこない問い**です。
検索エンジン（キーワード一致も意味の近さも）は、質問と答えの文書が言葉を
共有しているときだけ答えを見つけられます。共有していなければ、関係を辿る
仕組み（KG）だけが答えに到達できます。だから:

- **終端側の事実（経路の最後の原文にある具体的な内容）を答え**にする
- 質問は**始点側の状況の言葉だけ**で書く。途中の中継語（検査名・講習名など）と
  **終端の原文の見出し語・固有の言い回し**を質問文に書かない —
  それを見つけるのが検索側の仕事
- 答えは原文にある具体的な事実（条文番号・数値・要件・手順名）。単位・数値は明示

## 例（実際の評価結果から）

**良い例**（検索が解けなかった＝評価に使える問い）:

> 溶接金属から6 mm以内の部分に管や管台をねじ込みによって取り付ける穴を設ける
> 場合の溶接部について、どのような試験を行う必要があるか教えてください。

始点側の具体的な状況（6mm・ねじ込み穴）だけで書かれ、答えの原文（別規格の
試験規定）の言葉を含まない。検索は答えに届かず、関係を辿る必要が生じる。

**悪い例**（検索に一発で当てられた＝評価にならない問い）:

> 自動車に固定された状態で液化石油ガスを充塡する液化石油ガス自動車燃料装置用
> 容器（溶接容器に限る）の場合、経過年数によって再検査の周期はどう変わりますか？

「液化石油ガス自動車燃料装置用容器（溶接容器に限る）」は**答えの原文の見出し語
そのまま**。キーワード一致で即座に見つかる。
書き直すなら「自動車に固定して使う液化石油ガスの容器を使い続けたいが、
何年ごとに検査を受ければよいか」— 実務者の言葉に崩し、原文の見出しの
言い回しをそのまま写さない。

## 質問の文体

実務者が検索窓に実際に入力する依頼文として書く。試験問題ではない。

- 質問者は設計者・検査員・運転員。自分の作業を進めるために聞く
- 「〜を教えてください」「〜したいが何に従えばよいか」の形。
  命令形・試験文体（「〜を説明せよ」「〜を述べよ」）は禁止
- 対象（設備・材料・条件）は具体的に。ゴールは1つ（1問1答）
- **独立した2つの問いを「また」「これに関連して」で束ねない**
- 原文に無い用語・造語・文書ファイル名を書かない

```json
{{
  "question": "<質問文。日本語>",
  "answer": "<終端の事実を含む簡潔な模範回答>",
  "rationale": [
    {{"doc_id": "<原文ブロックの doc_id をそのまま>", "chunk_id": "<同 chunk_id>", "page": null, "text": "<該当チャンク内の連続した部分文字列>"}}
  ],
  "difficulty_rationale": "<経由するエンティティ数・必要チャンク数を定量で>"
}}
```

# 品質ルール

1. rationale は**各原文ブロックから1件ずつ**（2ブロックなら2件）
2. rationale.text は原文の連続した部分文字列（改変・要約しない）
3. 質問文に答えそのもの（具体的な数値・固有名）を書かない
