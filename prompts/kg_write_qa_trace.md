# 問いの作り方 — multi_hop との違い（重要）

この型は「答えの事実」ではなく**「根拠の系譜」**を問う。監査や検査立会で
「その要求はどの規定から来ているのか、たどって示してくれ」と言われる場面の再現。

- 質問は「〜はなぜ必要なのか / どの規定に基づくのか、**根拠を順に**教えてください」の形
- **答えには規定の識別子（規則名・条番号）を、経路の順に明記する**。
  例: 「まず◯◯規則第N条が〜を求め、その基準は△△解釈の第M条が〜と定めている」
- 質問文には識別子（条番号・規則名）を書かない — それを辿らせるのが問い
- **規定の名称は原文ブロックの doc_id にある文書の名称だけを使う**。原文に書かれて
  いない規則名・条番号を推測で補わない（別の規則の名前を当てはめるのは誤り）

## 質問の文体

実務者が検索窓に実際に入力する依頼文として書く。試験問題ではない。
「〜を説明せよ」等の命令形・試験文体は禁止。

# 出力スキーマ（厳守・JSON 1件のみ）

```json
{{
  "question": "<質問文。日本語。根拠の系譜を求める形>",
  "answer": "<経路の順に、各規定の識別子を明記した根拠の説明>",
  "rationale": [
    {{"doc_id": "<原文ブロックの doc_id をそのまま>", "chunk_id": "<同 chunk_id>", "page": null, "text": "<該当チャンク内の連続した部分文字列>"}}
  ],
  "difficulty_rationale": "<経由する規定数・必要チャンク数を定量で>"
}}
```

# 品質ルール

1. rationale は**各原文ブロックから1件ずつ**
2. rationale.text は原文の連続した部分文字列（改変・要約しない）
3. 答えの識別子（条番号・規則名）は**原文に書かれているものだけ**を使う
