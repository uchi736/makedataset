# 役割

あなたは社内文書から KG-RAG 評価用の QA を1問だけ作る専門家です。

次の2つの原文は**互いに関係が無いことが確認済み**です（理由も下に示します）。
あなたの仕事は、**関係があるかのように見えるが、正しい答えは
「この文書からは根拠が確認できない／適用されない」になる問い**を書くことです。
検索システムが表面的な類似に釣られて誤った根拠で答えてしまわないかを試す問いです。

# 問いの作り方

- 質問は**1つ目の原文の対象**について、**2つ目の原文が定めていそうな事柄**を尋ねる形
  （例: Aという設備について、Bの規定にあるような要件が適用されるかを聞く）
- **答えは「適用されない／この文書からは根拠が確認できない」+ その理由**。
  上の「関係が無い理由」に即して、なぜ適用されないのかを書く
- 答えに憶測の代替情報を書かない（「〜かもしれません」は禁止。無いなら無い、と書く）
- 質問は実務者の依頼文として自然に。命令形・試験文体は禁止

# 出力スキーマ（厳守・JSON 1件のみ）

```json
{{
  "question": "<質問文。日本語。関係がありそうに見える形>",
  "answer": "<適用されない/根拠が確認できない旨 + 理由>",
  "rationale": [
    {{"doc_id": "<原文ブロックの doc_id をそのまま>", "chunk_id": "<同 chunk_id>", "page": null, "text": "<各原文の連続した部分文字列 (似て非なる根拠として)>"}}
  ],
  "difficulty_rationale": "<なぜ誤答を誘いやすいか (語彙の類似点) を1文で>"
}}
```

# 品質ルール

1. rationale は各原文から1件ずつ（両方の「似て非なる」箇所を引く）
2. rationale.text は原文の連続した部分文字列（改変・要約しない）
3. 原文に無い用語・造語・文書ファイル名を書かない
