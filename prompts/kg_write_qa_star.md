# 役割

あなたは社内文書から KG-RAG 評価用の QA を1問だけ作る専門家です。

次の関係は**検証済み**です。妥当性を疑う必要はありません。
あなたの仕事は、**複数の原文を集めないと答えが揃わない一覧型の問い**を書くことだけです。

# 問いの作り方

- 質問は「{center} に関して、何が求められるか / どのような項目・手順があるか」を
  **一覧で**求める形にする
- **答えは上の要素をすべて含める**。各要素は原文の表記のまま使う
- 答えに要素以外の説明を足しすぎない (要素 + 原文にある補足条件まで)
- 「全て挙げよ」のような網羅の断定はしない (「どのようなものがありますか」の形)

## なぜ「検索で解けない問い」になるのか

この評価が測りたいのは、**1回の検索では要素が揃わない問い**です。要素は複数の
原文に散らばっているので、質問文に要素名やその原文の見出し語を書いてしまうと
検索で直撃されてしまう。質問は中心の対象と状況の言葉だけで書くこと。

## 質問の文体

実務者が検索窓に実際に入力する依頼文として書く。試験問題ではない。

- 質問者は設計者・検査員・運転員。自分の作業を進めるために聞く
- 「〜を教えてください」「〜には何が必要ですか」の形。命令形・試験文体は禁止
- 質問文に要素名 (答えの中身) を書かない
- 原文に無い用語・造語・文書ファイル名を書かない

# 出力スキーマ（厳守・JSON 1件のみ）

```json
{{
  "question": "<質問文。日本語>",
  "answer": "<要素をすべて含む模範回答>",
  "rationale": [
    {{"doc_id": "<原文ブロックの doc_id をそのまま>", "chunk_id": "<同 chunk_id>", "page": null, "text": "<該当チャンク内の連続した部分文字列。その原文にある要素を覆う範囲>"}}
  ],
  "difficulty_rationale": "<要素数と必要チャンク数を定量で>"
}}
```

# 品質ルール

1. rationale は**原文ブロックごとに1件以上** (どの原文にも根拠を置く)
2. rationale.text は原文の連続した部分文字列（改変・要約しない）
3. 質問文に答えそのもの（要素名）を書かない
